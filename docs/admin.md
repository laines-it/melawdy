# Базовая панель администратора

Откройте [панель](http://localhost:8080/admin.html) и войдите с email и паролем администратора. Учётная запись хранится в локальной PostgreSQL MeLawDy. Регистрации и управления обычными пользователями в этом каркасе нет.

## Первое создание и смена пароля

Из локального Python-окружения после `python -m alembic upgrade head`:

```sh
python -m backend.manage_admin --generate-password
```

Команда создаёт `admin@melawdy.local` и файл `.admin-credentials` с правами `0600`. Существующий файл не перезаписывается. Пароль существующего аккаунта сохраняется без явного `--reset-password`.

Вариант для работающего Compose с вводом своего пароля в скрытом приглашении:

```sh
docker compose exec api python -m backend.manage_admin --email admin@melawdy.local

# Явная смена пароля существующего администратора и отзыв его сессий
docker compose exec api python -m backend.manage_admin --email admin@melawdy.local --reset-password
```

Генерация пароля через Compose и копирование файла на хост показаны в README. Для нового email команда создаёт отдельного администратора. Email обычного пользователя не получает административные права автоматически.

## Статья

1. При необходимости создайте категорию и теги в соответствующих разделах.
2. Выберите «Статьи и материалы», заполните название, уникальный slug и хотя бы один текстовый раздел.
3. Сохраните как `draft`, чтобы оставить материал только в панели.
4. Для публикации выберите `published`. Пустая дата заполняется текущим временем; будущая дата откладывает появление на главной странице.
5. Теги и термины привязываются в разделах «Теги статей» и «Термины в статьях».

Текстовые разделы сохраняются как `content_item_chunks`. Embeddings не рассчитываются при сохранении; после изменения текста переиндексируйте контент по [инструкции поиска](search.md).

Публичная страница статьи — `/article.html?id=42`, где `42` — ID записи из `content_items`. Она вызывает `GET /api/v1/public/articles/42` и отображает чанки по `chunk_index`: первый в голубом вводном блоке, остальные в основном тексте. Пустые строки разделяют абзацы; строки с `#` / `##` / `###` создают заголовки, `-` / `*` — маркированный список, `1.` — нумерованный. HTML отображается как текст. Черновики и статьи с будущей датой публикации возвращают 404. Переход на страницу доступен из списка статей, результатов поиска и связанных популярных вопросов.

## Assessment

1. Создайте опрос (название, версия, активность).
2. В «Assessment: вопросы» выберите опрос, текст, тип вопроса, порядок и обязательность.
3. Для вариантов выбора создайте записи «Assessment: варианты ответов», указав вопрос, текст и значение ответа.
4. Добавьте возможные результаты в «Assessment: результаты»; при необходимости укажите рекомендованный материал или шаблон.
5. В «Assessment: правила» свяжите опрос с результатом, сохраните подготовленное условие как JSON-объект и укажите приоритет.

Панель сохраняет условия, но не исполняет их. Синтаксис условий и вычисление результатов должны быть реализованы после согласования правил. Главная страница показывает активные опросы и их вопросы для предварительного просмотра; ответы не отправляются и не сохраняются.

## Остальные разделы

Доступны Q&A, глоссарий, шаблоны документов, типы заявок, классы МКТУ и ставки пошлин. Поле файла в шаблоне хранит путь или ключ файла во внешнем хранилище; загрузки файлов через форму ещё нет. Зависимые записи выбираются по ID и названию, список содержит последние 500 записей.

Формы проверяют обязательные поля, enum, идентификаторы, точность денег и даты ставок. Ошибки уникальности и внешних ключей возвращаются как сообщение. Перед удалением требуется подтверждение в браузере; некоторые записи защищены связями в базе.

## Доступ

Сессия действует 8 часов. Cookie — `HttpOnly`, `SameSite=Strict`, путь `/api/`; токен сессии хранится в базе только как SHA-256-хеш. Изменения требуют CSRF-токен, получаемый при входе или восстановлении сессии. Выход и смена пароля отзывают соответствующие серверные сессии. Nginx ограничивает частоту запросов входа.

Для HTTPS-деплоя задайте `SESSION_COOKIE_SECURE=true`. Пароль первого администратора не встроен в код или миграцию. `ADMIN_PASSWORD` в окружении используется только для первоначального создания, когда переменная непустая.
