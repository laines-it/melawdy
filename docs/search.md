# Поиск по эмбеддингам и BM25

## Модель и ранжирование

Ветка `search-embeddings` использует локальный `SentenceTransformer("alekseevpavel04/multilingual-e5-small-ru-law")`. Hugging Face Inference Endpoint и API-токен не нужны. Модель скачивается при первом расчёте векторов и переиспользуется из дискового кэша; каждый процесс хранит загруженную модель в RAM. Релизный образ для VPS содержит веса и загружает их без сети.

Согласно [карточке модели](https://huggingface.co/alekseevpavel04/multilingual-e5-small-ru-law), векторы имеют 384 измерения, вход ограничен 512 токенами, обязательны префиксы `query: ` и `passage: `. Их добавляет `LegalEmbedder`; векторы нормализуются. Слишком длинные запросы отклоняются.

Для публичного поиска `ml.search_documents` собирает отдельные фрагменты примерно по 560 символов, объединяет короткие абзацы и добавляет заголовок статьи и раздела. URL, подписи авторов, блоки примечаний и отсылки к другим статьям в поисковые тексты не попадают. Исходные чанки и текст на странице сохраняются. Каждый фрагмент получает самостоятельный вектор; при разделении по 512 токенам заголовки повторяются в каждой части. Усреднения частей в этом индексе нет.

`ml.embedding_search.search_embeddings(query, session=session, limit=10)` кодирует только запрос. Из опубликованных материалов с наступившей датой публикации загружаются `content_search_fragments`; в RAM кешируются матрица и существующий `Bm25Index`. Кеш перестраивается при изменении состава фрагментов, векторов или заголовков. Для текущего небольшого корпуса используется точный перебор.

Ранг статьи объединяет максимум cosine similarity по её фрагментам, BM25 фрагментов и BM25 заголовков через reciprocal rank fusion (`k=20`). В BM25-запросе удаляются служебные вопросительные слова, но сохраняются отрицания. Заголовок участвует отдельным каналом, если покрывает хотя бы половину значимых слов запроса после русского стемминга. Полное совпадение заголовка без учёта регистра, пунктуации и ё/е имеет приоритет. Статьи возвращаются без дублей.

`SEARCH_MIN_SIMILARITY` задаёт минимальную cosine similarity (по умолчанию `0.40`), кроме точного совпадения заголовка. Порог применяется к каждому материалу до ограничения количества результатов, а не к RRF-оценке. Он проверен на локальной диагностической выборке, но не гарантирует отказ для любого постороннего запроса; при смене корпуса или модели его нужно переоценить.

API `GET /api/v1/public/search?query=...&limit=10` по умолчанию использует гибрид E5 + BM25 (прежнее имя параметра `method=embeddings` сохранено). Формат совпадает с веткой BM25: `{"article_ids": ["2", "3"], "title": "Заголовок первого материала", "summary": "Описание"}`. При отсутствии результатов возвращается `{"article_ids": [], "title": null, "summary": null}`. Для TF-IDF укажите `method=tfidf`. Страница также принимает прежний массив результатов при обновлении контейнеров по отдельности.

## Запуск через Docker Compose

Обычная сборка API устанавливает CPU PyTorch и sentence-transformers. Кэш модели сохраняется в Docker volume `model_cache`.

Из рабочего каталога ветки выполните:

```sh
docker compose up --build -d
```

`backend/entrypoint.sh` выполняет миграции, создаёт администратора из окружения, запускает `python -m ml.index_content`, затем `python -m ml.index_search_content` и только после успешного завершения обоих запускает Uvicorn. Поэтому каждый деплой и перезапуск рассчитывает недостающие embeddings автоматически. Готовые векторы пропускаются; если расчёт не нужен, модель не загружается в процесс индексатора. При ошибке или оставшихся пустых векторах процесс завершается с ненулевым кодом, API не запускается. Логи видны через `docker compose logs -f api`.

Миграция `0007_e5_embeddings` переводит колонку с 1024 на 384 измерения и очищает только несовместимые embeddings; тексты и остальные данные сохраняются. После перехода индексация перед запуском API восстанавливает векторы. Обратная миграция также требует пересчёта для прежней модели.

Миграция `0008_search_fragments` добавляет `content_search_indexes` (хеш исходного материала) и `content_search_fragments` (поисковые тексты и векторы). Исходные данные не переписываются. Триггеры удаляют устаревший поисковый индекс при изменении заголовка, добавлении, удалении или изменении исходного чанка. Повторный запуск пропускает неизменившиеся статьи. Замена поискового индекса статьи атомарна; параллельное изменение контента вызывает ошибку и требует повтора. До пересчёта изменённая статья не участвует в поиске.

Первый запуск может занять несколько минут; startup-проверке отведено 15 минут. Контекстный индексатор печатает прогресс, проверяет хеш исходного материала и сохраняет все фрагменты статьи одной транзакцией. После редактирования контента в работающем приложении пересчёт выполняется при следующем старте или вручную:

```sh
docker compose exec api python -m ml.index_search_content --batch-size 8
```

Для полного пересчёта добавьте `--force`.

```sh
docker compose exec api python -m ml.search --mode hybrid --query "как зарегистрировать песню" --limit 5
```

CLI в режиме `hybrid` использует ту же функцию, что и API, и возвращает уникальные материалы с выбранным поисковым фрагментом. Режим `embedding` оставлен для диагностики прежних векторов исходных чанков; `ml.index_content` поддерживает этот прежний индекс. Автоматической подмены embeddings на TF-IDF при ошибке нет. Неудачная загрузка модели возвращает 503, слишком длинный запрос — 422.

## Запуск Python без Docker

```sh
python -m pip install -r backend/requirements.txt
python -m pip install 'torch>=2.6,<3' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r ml/requirements.txt
python -m alembic upgrade head
python -m ml.index_content --batch-size 8
python -m ml.index_search_content --batch-size 8
```

PostgreSQL берётся из `.env` или `POSTGRES_*`. По умолчанию модель работает на CPU; устройство задаётся через `EMBEDDING_DEVICE`.

## Работа без сети

Можно заранее скачать модель в отдельный каталог:

```sh
python -m ml.download_model --output-dir models/multilingual-e5-small-ru-law
```

Для воспроизводимости команда принимает `--revision <commit-hash>`. Укажите `EMBEDDING_MODEL_PATH` с путём к скачанному каталогу: тогда SentenceTransformer использует `local_files_only=True`. В Docker каталог подключается так:

```sh
docker compose -f docker-compose.yml -f compose.ml.yml up --build -d
```

При сборке релизов `deploy/k3s/publish-release.sh` передаёт `DOWNLOAD_EMBEDDING_MODEL=true`: веса включаются в `/opt/embedding-model`. `get_embedder` автоматически выбирает этот каталог с `local_files_only=True`, что подходит для закрытой NetworkPolicy. Перед первым таким релизом обновите манифест API и серверный `deploy-release.sh`: CPU-модели выделены request 1 GiB / limit 2 GiB, startup и ожидание rollout увеличены до 15 минут. Манифесты применяются отдельно оператором, автоматическая смена образа не обновляет лимиты ресурсов.

## CLI и проверки

`TfidfIndex` использует униграммы/биграммы и cosine similarity. Режим `hybrid` соответствует публичному поиску E5 + BM25:

```sh
python -m ml.search --mode tfidf --query "авторское право"
python -m ml.search --mode hybrid --query "авторское право"
```

Юнит-тесты используют искусственные тексты, векторы и mock-модель, без БД и скачивания весов. Качество поиска и пороги cosine similarity следует оценивать на размеченных запросах к вашему корпусу. `/api/v1/analyze` остаётся заглушкой.
