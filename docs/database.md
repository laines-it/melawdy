# База данных MeLawDy

Python / FastAPI / SQLAlchemy 2 / psycopg 3 / Alembic, PostgreSQL 17 с pgvector.
Исходная схема заказчика сохранена в [schema.mmd](schema.mmd).

## Модели

Все классы доступны через `from backend.models import ...`.

| Модуль | Таблицы |
| --- | --- |
| `users.py` | `users` |
| `auth.py` | `admin_sessions` (служебная таблица) |
| `content.py` | `content_categories`, `content_items`, `content_item_chunks`, `content_tags`, `content_item_tags`, `glossary_terms`, `glossary_term_content`, `qa_pairs` |
| `assessments.py` | `assessment_surveys`, `assessment_questions`, `assessment_options`, `assessment_results`, `assessment_result_rules`, `user_assessments` |
| `fees.py` | `mktu_classes`, `application_types`, `fee_rates`, `fee_calculations`, `fee_calculation_classes` |
| `documents.py` | `document_templates`, `user_documents`, `document_status_history`, `request_history` |
| `favorites.py` | `user_favorites` |

Итого 25 доменных таблиц и служебная таблица `admin_sessions`. В `legacy.py` сохранены две таблицы первого каркаса с UUID: `documents` и `document_chunks`. Они обслуживают старый пример CRUD и не входят в новую предметную схему. Итого ORM управляет 28 таблицами.

Пример работы со связанными объектами:

```python
from backend.db import SessionLocal
from backend.models import ContentItem, ContentItemChunk, ContentType

with SessionLocal.begin() as session:
    item = ContentItem(title="Название", slug="example", type=ContentType.ARTICLE)
    item.chunks.append(ContentItemChunk(chunk_index=0, body="Текст материала"))
    session.add(item)
```

Материал создаётся в статусе `draft`. Для поиска необходимы `status=ContentStatus.PUBLISHED` и `published_at` не позже текущего времени. Публикация контента и юридическая проверка остаются отдельными действиями приложения.

## Начальное предложение enum-значений

В исходной диаграмме значения не перечислены. По запросу пользователя предложен следующий набор; это технический стартовый справочник, который можно уточнять новыми миграциями.

| PostgreSQL enum | Значения |
| --- | --- |
| `user_type` | `individual`, `organization`, `lawyer`, `admin` |
| `content_type` | `article`, `guide`, `faq`, `news` |
| `content_status` | `draft`, `published`, `archived` |
| `question_type` | `single_choice`, `multiple_choice`, `text`, `boolean` |
| `document_type` | `contract`, `claim`, `application`, `other` |
| `document_status` | `draft`, `in_progress`, `completed`, `archived` |
| `deadline_status` | `none`, `upcoming`, `overdue`, `completed` |

`document_status` используется и в документе, и в истории статусов; `document_type` — в шаблоне и пользовательском документе. В БД сохраняются строковые значения enum в нижнем регистре. Админ-API допускает только активных пользователей с `user_type=admin`; права остальных ролей ещё не реализованы. Автоматические переходы статусов и напоминания этой миграцией не создаются.

## Типы и ограничения

- Первичные ключи новых сущностей: `BIGINT GENERATED BY DEFAULT AS IDENTITY`; таблицы связей имеют составные ключи.
- Даты и время событий: `TIMESTAMPTZ`, даты срока/действия ставки: `DATE`. `updated_at` обновляется триггером, включая прямой SQL.
- Деньги: `NUMERIC(14, 2)` / Python `Decimal`, с запретом отрицательных сумм.
- Условия, ответы, расчёты, содержимое документов и параметры запросов: `JSONB`.
- Индексы внешних ключей, уникальные email/slug/code, уникальный номер чанка внутри материала; сортировки и номера чанков неотрицательны.
- `content_item_chunks.embedding`: nullable `vector(384)`, HNSW cosine index. При изменении `body` триггер сбрасывает embedding в `NULL`; его нужно пересчитать.
- `content_search_indexes` хранит хеш версии поискового представления статьи; `content_search_fragments` хранит независимые векторы `vector(384)` очищенных фрагментов. Изменения исходных чанков и заголовка удаляют индекс статьи; он восстанавливается при следующей индексации.
- `content_item_chunks.tsv`: вычисляемый сохранённый `to_tsvector('russian', body)` с GIN-индексом. Это поле полнотекстового поиска PostgreSQL; TF-IDF вычисляется отдельно через scikit-learn по исходному тексту.
- Ставки имеют проверку диапазона дат и уникальность `(application_type_id, mktu_class_id, is_urgent, valid_from)` с `NULLS NOT DISTINCT`. Сервис расчёта отклоняет пересечение действующих периодов для выбранной процедуры, класса и срочности. Сумма — точная ставка за одну процедуру, умноженная на количество процедур; льготы и доплаты за другие классы не заданы.
- МКТУ: номер класса от 1 до 45. Сами справочники и юридические ставки не заполняются вымышленными данными.

## Допущения, которых нет в исходной диаграмме

Диаграмма не задаёт nullable, длины строк, значения по умолчанию и поведение удаления. Приняты следующие решения:

- Категория и автор материала необязательны; публикация требует даты. Q&A может не иметь связанной статьи/категории.
- Рекомендации результата опроса необязательны. В двух стрелках ER-диаграммы направление рекомендаций противоречит FK-полям; реализация следует FK: результат ссылается на материал и шаблон.
- Результат прохождения опроса может быть `NULL` до вычисления. Владелец прохождения, документа, расчёта и записи истории запросов обязателен.
- Родитель категории, шаблон документа, срок, файловый ключ, прежний статус и автор изменения могут отсутствовать.
- Чанки, привязки тегов и терминов удаляются с материалом (`CASCADE`). История, прохождения и расчёты защищены от удаления связанных записей (`RESTRICT`); необязательные рекомендации и ссылки на автора/шаблон получают `SET NULL`.
- `file_path` хранит ключ объекта в MinIO/S3, а не байты файла или временную подписанную ссылку.
- Поля JSONB следует заменять новым объектом при изменении вложенных данных: обычный JSONB не отслеживает вложенные in-place изменения автоматически.
- История статусов записывается приложением в той же транзакции, что и изменение документа; автоматического аудита и движка юридических правил пока нет.

## Миграции

`0001_initial` оставлена неизменной. `0002_domain_schema` создаёт новые таблицы, enum-типы, индексы и триггеры; старые данные не переименовывает и не удаляет. Миграция содержит фиксированный снимок схемы и не импортирует текущие ORM-модели.

`0003_admin_sessions` добавляет таблицу с SHA-256-хешем токена, пользователем, временем создания и сроком действия сессии. Откат этой ревизии завершает все админ-сессии, сохраняя пользователей. Встречающаяся в существующей локальной базе таблица `app_metadata` не управляется ORM и исключена из автогенерации Alembic; её данные сохраняются.

Ревизии `0004_csrf_token`, `0005_auth_security` и `0006_user_favorites` продолжают ту же цепочку, что и в `main`: обязательный хеш CSRF-токена сессии, счётчик неудачных входов и срок блокировки пользователя, затем избранные материалы. `frontlayout` поддерживает базы, уже обновлённые до `0006_user_favorites`; откат или изменение `alembic_version` для запуска этой ветки не нужны.

```sh
python -m alembic upgrade head
python -m alembic current
python -m alembic check

# Подготовить SQL без подключения к БД
python -m alembic upgrade head --sql > migration.sql

# После следующего изменения моделей создать и проверить новую ревизию
python -m alembic revision --autogenerate -m "Describe schema change"
```

Нужен `CREATE EXTENSION vector` в целевой базе (в Compose доступен пользователю и выполняется первой миграцией). Миграции применяются отдельно от загрузки ML-модели.

`alembic downgrade 0001_initial` удаляет новые 25 доменных таблиц, админ-сессии и их данные, сохраняя legacy-таблицы. Для работающей базы откат требует заранее подготовленного резервного копирования.

Локальные юнит-тесты проверяют соответствие исходной ER-схеме, связи объектов и генерацию SQL без БД. CI дополнительно проверяет реальную PostgreSQL, совпадение моделей со схемой, JSONB/Decimal, pgvector, триггеры и downgrade/upgrade.
