# Конструктор документов

Страница `/documents.html` показывает активные шаблоны из API. Ссылки
`?template=ID` открывают новый документ, `?document=ID` — сохранённый документ
текущего пользователя. Страница доступна из шапки сайта, проверки музыки и
личного кабинета. Frontend использует обычные HTML, CSS и JavaScript.

Заполнение и просмотр доступны гостям. При сохранении или скачивании откроется
форма входа: переход на другую страницу не требуется, введённые данные остаются
в памяти страницы. Для регистрации можно открыть новую вкладку. Персональные
данные не записываются в localStorage. Черновики сохраняются явно кнопкой
«Сохранить черновик»; браузер предупреждает при уходе с несохранёнными изменениями.

## Публикация шаблона

В админ-панели, в разделе «Шаблоны документов», доступны поля «Разделы и поля
конструктора (JSON)» и «Блоки документа (JSON)». У существующего шаблона без
структуры поля автоматически извлекаются из подстановок `{{name}}` в тексте.

В [examples/coauthors-template.json](examples/coauthors-template.json) приведён
пример данных для создания шаблона через `POST /api/v1/admin/templates` с
сессией администратора и CSRF-токеном. Его `schema_json` и `structure_json`
можно также скопировать в соответствующие поля админ-панели. Пример иллюстрирует
формат на основе соглашения из `backend/agreement.py`; публикация и проверка
содержания остаются под управлением администратора. Шаблоны автоматически в
базу не добавляются.

### Импорт скриптом

Использованный для добавления соглашения импорт вынесен в `backend/import_template.py`.
Он проверяет JSON через `TemplateInput`, добавляет запись транзакцией с
`ON CONFLICT (slug) DO NOTHING` и выводит ID и число разделов/блоков.
Повторный запуск выводит `"created": false`, сохраняя существующую запись,
включая изменения администратора. Пароли не встроены в скрипт: используются
`POSTGRES_*` из окружения и локального `.env`, как у API.

В PowerShell из корня репозитория, с установленными Python-зависимостями проекта:

```powershell
# Посмотреть запущенные контейнеры и версию схемы БД.
docker compose ps
docker compose exec -T postgres psql -U melawdy_app -d melawdy -X -c "SELECT version_num FROM alembic_version;"

# Добавить соглашение соавторов в БД из настроек backend/config.py.
.\.venv\Scripts\python.exe -m backend.import_template

# Или явно указать JSON другого шаблона.
.\.venv\Scripts\python.exe -m backend.import_template docs/examples/coauthors-template.json

# Проверить опубликованный шаблон через сайт.
Invoke-RestMethod 'http://localhost:8080/api/v1/public/templates'
```

Для локального Compose без `.env` используются `localhost:5432`, база `melawdy`
и роль `melawdy_app`. Если они переопределены, задайте соответствующие `POSTGRES_*`
для локального Python. В команде `psql` выше также замените роль/базу на свои.

Чтобы использовать подключение уже работающего API-контейнера, скопируйте в него
скрипт и JSON. Пересборка образа не требуется:

```powershell
docker compose cp backend/import_template.py api:/tmp/import_template.py
docker compose cp docs/examples/coauthors-template.json api:/tmp/coauthors-template.json
docker compose exec -T api python /tmp/import_template.py /tmp/coauthors-template.json
```

API-контейнер должен иметь актуальные модели и миграцию `0008_template_constructor`.
В Linux с локальным Python эквивалентная команда:
`python -m backend.import_template docs/examples/coauthors-template.json`.

`schema_json.sections` — массив разделов в порядке отображения:

| Поле | Назначение |
| --- | --- |
| `id`, `title` | Идентификатор и название раздела |
| `description`, `icon` | Необязательные пояснение и значок |
| `fields` | Массив полей раздела |

Поле формы содержит `name` (поддерживается путь `author.name`), `label`,
`type` (`text`, `textarea`, `email`, `tel`, `date`, `number`, `select`, `radio`,
`boolean`), `required`, `default`, `placeholder`, `hint`. Для чисел доступны
`min`, `max`, `step`, для текста — `max_length`. Варианты `options` — строки
или объекты `{ "value": "individual", "label": "Физическое лицо" }`.
Последовательные поля с одинаковым `group` объединяются в карточку.
`when`, например `representation == proxy`, управляет видимостью поля;
скрытые поля не участвуют в проверке обязательности. Имена полей должны быть
уникальны в пределах шаблона.

`structure_json.blocks` использует существующий формат бэкенда:
`id`, `template`, необязательное `when`. Дополнительное `section` связывает
блок с разделом формы для подсветки и прокрутки; иначе используется `id`.
Подстановки `{{name}}` и условия `field == value` / `field != value` работают
так же, как в `backend/render.py`. Условия поддерживают `true` / `false`.
Нет HTML или произвольного исполнения JavaScript. Неописанные в форме
подстановки добавляются в раздел «Дополнительные параметры».

## Сохранение и выгрузка

Конструктор сохраняет `title`, `template_id`, `document_type` и параметры в
`content_json` через существующие `POST/PATCH /api/v1/cabinet/documents`.
Черновик можно сохранить с незаполненными полями. Перед выгрузкой проверяются
все видимые обязательные поля, включая поля других разделов. Повторное
сохранение и скачивание обновляют тот же документ.

`GET /api/v1/cabinet/documents/{id}/download` проверяет владельца, формирует
текст теми же серверными функциями, что и `/documents/generate`, и возвращает
DOCX. Шаблоны без `structure_json` используют `body`. Старые документы без
шаблона и удалённые/неактивные публичные шаблоны показывают понятное сообщение.

## Проверка

```sh
node --test web/tests/*.test.js
python -m pytest -q
```

JS-тесты проверяют подстановки, условия, построение полей и бинарный ответ API;
Python-тесты — публичный контракт шаблона, сохранение структуры через админку,
выгрузку DOCX и ограничение доступа владельцем.
