# CLEWS в Google Colab

В папке два самостоятельных ноутбука:

- `CLEWS_site_demo.ipynb` — ручной запуск задания с `/check/` и отправка результата на сайт.
  Настройка сервера и ключа описана в [инструкции демонстрации](../README.md).
- `CLEWS_music_search.ipynb` — поиск по загруженным файлам без сайта; инструкция ниже.

Модель не обучается:
используются опубликованные веса CLEWS. Запуск модели, установка зависимостей и
проверка в Google Colab при подготовке файлов не выполнялись.

## Что сделать пользователю

1. Сохранить файл `CLEWS_music_search.ipynb` из этой папки на свой компьютер.
2. Открыть <https://colab.research.google.com/> под своим Google-аккаунтом.
3. Выбрать **Файл → Загрузить блокнот** и указать скачанный `.ipynb`.
4. Выбрать **Среда выполнения → Сменить среду выполнения → GPU**. Предпочтительно T4:
   исходные зависимости используют PyTorch 2.3.1 и CUDA 12.1.
5. Выполнять ячейки по порядку кнопками ▶. Первые ячейки устанавливают отдельное
   окружение Python 3.11 и скачивают официальный архив весов (~8,7 GB).
6. В разделе **5. Исследуемая песня** загрузить один аудиофайл.
7. В разделе **6. Песни для сравнения** загрузить один или несколько других файлов.
   Для первой попытки достаточно 2–5 записей. Интернет-поиска по песням здесь нет.
8. Запустить раздел **7. Найти похожие фрагменты**. Затем раздел 8 покажет таблицу
   кандидатов и карту расстояний. В ячейке прослушивания выбрать `MATCH_NUMBER`.
9. В разделе 9 скачать ZIP с JSON/CSV. Включить `EXPORT_EMBEDDINGS`, если нужно
   дополнительно сохранить вычисленные векторы.

Каждый входной файл должен содержать от 20 секунд до 30 минут аудио.
Поддерживаются MP3, WAV, FLAC, OGG, M4A, AAC, WebM. Декодирование выполняет FFmpeg.

Чтобы проверить другую песню против той же коллекции, повторить ячейку загрузки
исследуемой песни и разделы 7–9. Чтобы добавить записи в коллекцию, повторить раздел 6.
Папка `references` накапливает загруженные записи; удалять их можно через панель файлов
Colab либо Google Drive. Ошибки и исключения выводятся отдельно.

## Сохранение между сеансами

В первой ячейке можно включить `USE_GOOGLE_DRIVE = True`. После разрешения доступа
папка `Мой диск/CLEWS_demo` будет содержать аудио, веса, кэш векторов и отчёты.
Не нужно включать эту опцию для одноразового запуска. Без Drive файлы исчезнут после
удаления временной машины Colab; скачивайте результаты перед завершением работы.
Архив весов временно хранится в машине Colab, а затем удаляется. Из него сохраняются
только выбранный checkpoint DVI и соответствующая конфигурация.

## Что означает результат

- Каждая запись разбивается на полные окна длительностью из конфигурации весов
  (обычно 20 секунд). По умолчанию окна начинаются каждые 5 секунд; последнее окно
  дополнительно покрывает конец записи. Фрагменты не дополняются повторением аудио.
- Пропускаются окна с RMS ниже 0,0001. Это простой фильтр тишины, не детектор музыки.
- Модель извлекает векторы небольшими пакетами; по умолчанию `BATCH_SIZE = 1`.
- Расстояние — квадрат евклидова расстояния, делённый на размерность вектора,
  как в исходной сегментной метрике CLEWS. Векторы не нормализуются дополнительно.
- Для каждого файла возвращаются до трёх лучших пар окон с подавлением близких
  перекрывающихся повторов. Список сортируется по расстоянию: меньше — ближе.
- Это собственная простая процедура ранжирования фрагментов поверх исходной модели,
  а не полное воспроизведение официального ранжирования треков CLEWS.
- Ближайший кандидат может быть несходным. Универсального порога и вероятности
  плагиата здесь нет. Прослушивание и оценка контекста остаются необходимыми.
- Полностью идентичные исходному файлы исключаются по SHA-256. Перекодированная
  копия имеет другой хеш и может попасть в результат.
- Векторы кэшируются по содержимому аудио, весам, конфигурации, версии программы
  и параметрам извлечения. Замена файла или параметров вызывает перерасчёт.

## Если возникла ошибка

- При нехватке GPU-памяти использовать `BATCH_SIZE = 1` и более короткие записи.
- Если GPU не выделена, программа допускает CPU; обработка будет медленнее.
- При ошибке совместимости CUDA выбрать T4. Новейшее оборудование может требовать
  обновления согласованной пары PyTorch/torchaudio.
- Если Zenodo прервал скачивание, повторить ячейку весов. Поддерживается продолжение;
  после несовпадения MD5 повреждённый архив удаляется.
- После отключения Colab заново выполнять ячейки по порядку. Сохранённые в Drive
  веса и векторы используются повторно.

## Файлы и источники

- `CLEWS_music_search.ipynb` — переносимый ноутбук: исходный код программы встроен
  внутрь, скачивать другие файлы этой папки для Colab не нужно.
- `clews_search.py` — тот же самостоятельный код поиска для чтения и ручного запуска
  в подготовленном Python-окружении.
- CLEWS: <https://github.com/sony/clews>, commit
  `517de18676e08799b51c6597a0f2af61f7a70799`; код под MIT.
- Веса: <https://zenodo.org/records/15045900>; архив `clews.zip`, опубликованная MD5
  `1cc63438b41f7b4421ad67be7fe0cd15`.
- Статья: <https://arxiv.org/abs/2502.16936>.
- Лимиты Colab: <https://research.google.com/colaboratory/faq.html>.

Лицензия кода CLEWS не предоставляет права на аудио и не заменяет проверку условий
использования весов. Встроенного каталога Covers80 или Discogs-VI в ноутбуке нет.
