# Ручная демонстрация CLEWS: от сайта до результата

Схема: посетитель загружает песню на `/check/` → оператор получает номер задания →
оператор запускает CLEWS в Colab → результат автоматически возвращается на сайт.
Colab обращается к сайту по HTTPS. Туннель и публичный API в Colab не нужны.

## 1. Один раз развернуть код сайта

Изменения кода нужно развернуть на сервере. Сам rebase не обновляет VPS.
Для существующего production на k3s сначала отправьте ветку в GitHub, создайте PR
в `main`, слейте его и дождитесь успешного workflow **Tests / Deploy main to VPS**.
Это обновит образы API и web. Инфраструктура очереди включается отдельно ниже.
Не запускайте `kubectl apply -k deploy/k3s` с локальными старыми тегами образов.

## 2. Один раз включить очередь на VPS с k3s

Команды этого раздела выполнять на VPS под root, **после развёртывания нового кода**.
Они сохраняют текущие теги образов API/web и не меняют PostgreSQL.

Создайте один секрет. Повторное создание файла с новым значением меняет ключ;
тогда такое же новое значение понадобится указать в Colab.

```sh
install -d -m 700 /root/.config/melawdy
(umask 077; python3 -c 'import secrets; print(secrets.token_urlsafe(32), end="")' > /root/.config/melawdy/clews-worker-token)
k3s kubectl -n melawdy create secret generic melawdy-clews \
  --from-file=worker-token=/root/.config/melawdy/clews-worker-token \
  --dry-run=client -o yaml | k3s kubectl apply -f -
```

Создайте диск очереди:

```sh
k3s kubectl -n melawdy apply -f - <<'YAML'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: music-check-data
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: local-path
  resources:
    requests:
      storage: 1Gi
YAML
```

Подключите диск и настройки к существующему API:

```sh
k3s kubectl -n melawdy patch deployment api --type strategic --patch-file /dev/stdin <<'YAML'
spec:
  template:
    spec:
      securityContext:
        fsGroup: 10001
      containers:
        - name: api
          env:
            - name: MUSIC_CHECK_ENABLED
              value: "true"
            - name: MUSIC_CHECK_DATA_DIR
              value: /var/lib/melawdy/music-check
            - name: MUSIC_CHECK_WORKER_TOKEN
              valueFrom:
                secretKeyRef:
                  name: melawdy-clews
                  key: worker-token
          volumeMounts:
            - name: music-check-data
              mountPath: /var/lib/melawdy/music-check
      volumes:
        - name: music-check-data
          persistentVolumeClaim:
            claimName: music-check-data
YAML
k3s kubectl -n melawdy rollout status deployment/api --timeout=900s
```

Откройте `https://lawmposer.ru/api/v1/public/capabilities`.
В `music_check` должно быть `"available": true` и `"mode": "manual_colab"`.
На `https://lawmposer.ru/check/` должна стать доступна загрузка.
Сохраните настройки в вашей серверной копии манифестов: повторное применение
варианта с `MUSIC_CHECK_ENABLED=false` снова выключит демонстрацию.

Если используете **Docker Compose вместо k3s**: этот раздел с kubectl пропустите.
В `.env` задайте `MUSIC_CHECK_ENABLED=true` и `MUSIC_CHECK_WORKER_TOKEN` (случайный
секрет от 32 символов), затем выполните `docker compose up -d --build api web`.
Сайт должен быть доступен из Colab по публичному HTTPS-адресу; `localhost` не подойдёт.

## 3. Подготовить Colab

1. Скачайте **CLEWS_site_demo.ipynb** из папки `colab` рядом с этой инструкцией.
   После обновления сайта его можно скачать по адресу
   `https://lawmposer.ru/api/v1/music-check/notebook`.
2. Откройте <https://colab.research.google.com/>. Через **Файл → Загрузить блокнот**
   выберите этот файл. Для работы с сайтом нужен именно `CLEWS_site_demo.ipynb`.
3. В настройках среды выполнения выберите **GPU**, предпочтительно **T4**.
4. В первой ячейке оставьте `USE_GOOGLE_DRIVE = False` для первого запуска.
   Для сохранения коллекции, весов и кэша между сеансами поставьте `True`
   и разрешите доступ к своему Google Drive.
5. Выполните разделы **1–4** кнопками ▶ по порядку. Дождитесь завершения каждого.
   Первый запуск скачает архив весов около **8,7 GB** и подготовит окружение.
6. В боковой панели Colab откройте **Секреты** (значок ключа). Добавьте секрет
   с именем **MUSIC_CHECK_WORKER_TOKEN**, вставьте значение из файла
   `/root/.config/melawdy/clews-worker-token` на VPS и разрешите доступ ноутбуку.
   При Compose берите значение из `.env`. Не вставляйте ключ в исходный код ячеек.
   Если не пользоваться Colab Secrets, раздел 5 запросит ключ в скрытом поле.

## 4. Провести первую проверку

1. На сайте откройте `/check/`, выберите исследуемую запись и нажмите
   **«Отправить на проверку»**. Вместо выбора файла можно нажать **«Записать с микрофона»**,
   разрешить доступ, записать от 20 секунд до 5 минут, остановить запись и прослушать её.
   Только после нажатия «Отправить на проверку» запись передаётся на сервер. Скопируйте двузначный номер задания (например, 17). Страницу оставьте открытой.
2. В разделе **5** ноутбука укажите `SITE_URL = "https://lawmposer.ru"`
   (адрес корня сайта, без `/check/`) и укажите этот двузначный номер в `JOB_ID`, например `17`. Нажмите ▶.
3. В разделе **6** нажмите ▶ и загрузите **песни для сравнения** через выбор файлов.
   Для первой демонстрации достаточно 2–5 записей. Это ваша поисковая коллекция;
   встроенной базы или поиска по всему интернету нет. Точную копию исследуемого
   файла программа исключает, поэтому для демонстрации возьмите другую запись,
   например кавер или другую версию произведения.
4. В разделе **7** нажмите ▶ и дождитесь завершения вычислений и отправки отчёта.
   Эта кнопка запускает обработку конкретного задания вручную.
5. Вернитесь на сайт: результат появится автоматически при обновлении статуса
   (примерно раз в 5 секунд). Можно нажать **«Обновить статус»**. В карточке результата нажмите
   **«Послушать найденный отрывок»** — появится MP3-плеер. Кнопка
   **«Послушать мой отрывок»** воспроизводит соответствующий участок вашей песни.
6. Раздел **8** Colab необязателен: там можно дополнительно послушать обе записи
   и посмотреть карту расстояний. Раздел **9** позволяет скачать отчёт.

Ограничения файла на сайте: **32 MiB**, MP3/WAV/FLAC/OGG/M4A/AAC/WebM.
Длительность для обработки: **20 секунд — 30 минут**.
Результат показывает кандидатов, таймкоды и расстояние: меньше — ближе.
Colab передаёт на сайт до 5 коротких найденных отрывков по 256 КиБ максимум;
они учитываются в квоте хранения очереди и удаляются вместе с заданием.
Для воспроизведения нужен обновлённый ноутбук и новая проверка.
Это не процент плагиата. Задание хранится 24 часа; попытка обработки действует час.

## 5. Следующая песня и повторный сеанс

Для новой песни создайте новое задание на сайте, замените `JOB_ID` и повторите
только разделы **5 и 7**. Коллекция останется той же. Для добавления новых записей
дополнительно повторите раздел 6.

Если Colab отключился, заново выполните подготовку по порядку. При включённом
Google Drive сохранённые веса и кэш используются повторно. Обработку каждого
нового задания всё равно запускает оператор; закрытый ноутбук задания не выполняет.
При ошибке можно заново выполнить раздел 5 и затем 7. Если только отправка отчёта
оборвалась, сначала проверьте сайт: уже завершённое задание повторно не запускается.
